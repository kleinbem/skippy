# Anonymous analytics

Skippy reports a small amount of anonymous usage data to its maintainers so
we can see which platforms and hardware to support, how fast real models load
and generate, and whether speculative decoding and the prompt cache pay off
outside our lab. Official release builds have an analytics key compiled in,
so for them it is on by default, disclosed on first run, and can be turned
off with a persistent preference. A build with no key, compiled in or set at
run time, reports nothing at all.

This page is the complete description of what is collected. If something
happens that is not on this page, it is a bug.

## Turning it off

```bash
skippy analytics disable
```

That records the choice in Skippy's analytics state directory, and it
survives restarts and upgrades. Any of these also turns reporting off:

| Control | Effect |
|---|---|
| `skippy analytics disable` | Save a reporting opt-out across runs |
| `skippy analytics enable` | Save a preference to report when a project key and process settings allow it |
| `SKIPPY_ANALYTICS=0` | Off for one invocation or one shell |
| `DO_NOT_TRACK=1` | Off, honoring the [console opt-out convention](https://consoledonottrack.com) |
| `CI=true` (or another CI variable) | Off automatically; CI runs are not users |
| A build with no analytics key | Off; source builds report nothing unless `SKIPPY_POSTHOG_KEY` is set at run time |

These settings are read when a process starts. To see what your machine is
doing:

```bash
skippy analytics status
```

A project key is required. When a key is present, an explicit
`SKIPPY_ANALYTICS` value takes precedence over `DO_NOT_TRACK`, the saved
preference, and CI detection. Values `1`, `true`, `yes`, and `on` enable
reporting. Other set values disable it. Without an override, Skippy honors
`DO_NOT_TRACK`, a saved opt-out, and CI detection in that order. An unreadable
saved preference disables reporting.

## Skippy inside another product

When Skippy runs inside another product, such as Mesh LLM, that product
decides whether reporting is on, shows its own first-run notice, and supplies
its own anonymous install identifier. Its opt-out turns Skippy's reporting off
too. Skippy then reports only the engine events below (`model_load`,
`host_profile`, and `generation`), each tagged with the product's name and
version.

## What is collected

Every event carries:

| Property | Example | Why |
|---|---|---|
| `distinct_id` | `9f1c…` | A random UUID generated on first run, or the embedding product's |
| `skippy_version` | `0.81.0` | Which versions are in the field |
| `host`, `host_version` | `skippy-cli`, `mesh-llm` | Which program Skippy is running inside |
| `build_channel` | `release`, `prerelease`, `development` | Whether pre-releases get real use |
| `os`, `arch` | `macos`, `aarch64` | Which platforms to prioritize |
| `exec_env` | `plain`, `container`, `ci`, `service` | Whether a run came from someone's machine or from throwaway infrastructure |
| `internal` | `false` | `true` for development builds, CI, and machines that set `SKIPPY_ANALYTICS_INTERNAL=1`, so the maintainers' own traffic can be excluded |

And one of these events:

| Event | Extra properties | What it answers |
|---|---|---|
| `install_first_run` | none | How many installs there are (standalone only) |
| `install_updated` | `from_version` | Whether people upgrade, and how fast a release spreads (standalone only) |
| `cli_command` | `family` (`models`, `runtime`, `doctor`, `gpu_benchmark`, …), `outcome` (`completed`, `failed`) | Which commands are used, and which fail (standalone only) |
| `serve_started` | `surface` (`public`, `stage`) | How `skippy serve` is used (standalone only) |
| `serve_stopped` | `session_length` (`under_1m`, `1m-15m`, …), `succeeded` | Whether servers stay up (standalone only) |
| `model_load` | the model properties below, `load_ms`, `outcome` (`loaded`, `failed`) | How long models take to load, and which fail |
| `host_profile` | see below | What hardware Skippy runs on |
| `generation` | see below | How fast real generations are |

`host_profile` is sent once per serving process:

| Property | Example | Notes |
|---|---|---|
| `gpu_model` | `apple-m1-pro`, `nvidia-geforce-rtx-4090`, `none`, `unreported` | The first GPU's name, lowercased and hyphenated. `none` means no GPU was found |
| `gpu_family` | `apple-m1`, `rtx-4090` | `gpu_model` without vendor words, form factor and tier |
| `gpu_count` | `1`, `3-4` | Bucketed |
| `vram_gb`, `system_ram_gb` | `24`, `64` | Memory in whole GiB |
| `unified_memory` | `true` | Whether the GPU shares system memory |
| `backend` | `metal`, `cuda`, `rocm`, `vulkan`, `cpu` | The backend this machine serves on |
| `backend_metal`, `backend_cuda`, `backend_rocm`, `backend_vulkan` | `true` | Which backends this machine can run |

`generation` is sent for each generation, at most 30 per minute per process.
When some were skipped, the next one carries a `weight` saying how many
generations it stands for. It carries the machine's `backend`, `gpu_family`
and `vram_gb`, and:

| Property | Example | Notes |
|---|---|---|
| `model`, `model_arch`, `model_params`, `model_moe`, `model_family`, `dflash_draft` | `Qwen3-8B-Q4_K_M`, `redacted` | See [Model names](#model-names) |
| `weight` | `1`, `12` | Generations this event represents |
| `request_kind` | `agentic`, `chat`, `completion` | `agentic` when tools were offered or the history carries tool results |
| `tools_offered`, `tool_results`, `system_prompt` | `true` | Whether each was present. Never the tools, their names, or any message text |
| `user_turns` | `1`, `3-4` | User messages in the history, bucketed |
| `serving` | `local`, `split` | Whole model, or stage 0 of a split |
| `downstream_lanes`, `concurrency_limit` | `4`, `2` | Persistent lanes to the next split stage, and generations admitted at once |
| `context_size`, `prompt_tokens`, `completion_tokens`, `context_tokens`, `context_fill`, `context_band` | `32768`, `3000`, `200`, `3200`, `0.0977`, `2k-8k` | Token counts only, never tokens |
| `cached_prompt_tokens`, `prefill_tokens`, `cache_hit_kind` | `2000`, `1000`, `prefix` | How much of the prompt the KV cache saved |
| `queue_wait_ms`, `restore_ms`, `prefill_ms`, `decode_ms`, `ttft_ms`, `total_ms` | `512.4` | Timings |
| `prefill_tps`, `decode_tps` | `2000`, `50` | Tokens per second |
| `finish_reason` | `stop`, `length` | Why generation ended |
| `spec_strategy`, `spec_allowed`, `spec_stand_down` | `dflash`, `true`, `gate_trial` | The speculative decoding strategy, whether the speculation gate let this generation use it, and why not when it did not |
| `spec_draft_cap`, `spec_window_max`, `spec_runahead_tokens` | `15`, `16`, `0` | The bounds speculation ran under |
| `spec_proposed_tokens`, `spec_accepted_tokens`, `spec_acceptance`, `spec_windows`, `spec_accepted_per_window` | `300`, `150`, `0.5`, `50`, `3` | Draft tokens proposed and accepted, overall and split into draft-model/N-gram (`spec_draft_*`) and native MTP/split DFlash (`spec_mtp_*`) |
| `activation_codec`, `activation_prefill_bytes`, `activation_decode_bytes` | `f16` | Split only: bytes sent to the next stage |

### Model names

A model is named only by the catalog entry it was loaded from. A local file,
an alias given with `--model-id`, a private repository, or a name a client
sent is `redacted`, and is described only by its architecture and a coarse
parameter count where the loader knows them.

## What is never collected

- **Prompts, completions, and any model input or output.** The analytics code
  receives counts and timings only, and its API cannot carry free text.
- **File paths and local model names.** See [Model names](#model-names).
- **Your IP address or location.** Every event sets `$geoip_disable` and a
  null `$ip`, and the project discards client IP data at ingestion.
- **Hostnames, usernames, MAC addresses, or hardware serials.** The hardware
  probe can see device IDs and bus addresses; the analytics code never reads
  them.
- **API keys, tokens, or settings values.**

## The install identifier

A random v4 UUID, created on the first standalone run, in Skippy's analytics
state directory: `SKIPPY_DATA_DIR/analytics` when that is set, otherwise the
platform's local data directory (`~/Library/Application Support/skippy/analytics`
on macOS, `~/.local/share/skippy/analytics` on Linux). Delete the file to
reset it.

## Verifying what a build sends

```bash
SKIPPY_POSTHOG_HOST=http://127.0.0.1:8000 \
SKIPPY_POSTHOG_KEY=phc_test \
SKIPPY_ANALYTICS=1 \
  skippy doctor
```
